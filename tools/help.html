Quick Start

  1. Load a marked HTML file using the Load HTML File button.
  2. Drag any red page marker badge to move it. A blue line shows where it will land — drop between words.
  3. Download the corrected file. It saves as corrected_YYYY-MM-DD_HH-MM.html.
Tip: Your work auto-saves to the browser after every change. If you refresh or close the tab, you'll be asked whether to restore it.

  • Esc — Exit Add Marker mode

Auto-save & Recovery

The editor automatically saves your work to the browser's local storage after every change. When you reopen the editor:

  • If recent work is found, you'll be prompted: "Found unsaved work from X minutes ago. Restore it?"
  • Click OK to continue where you left off (no need to reload the file).
  • Click Cancel to start fresh.

What can cause data loss

  • Clearing browser data or cache
  • Saved data older than 7 days (auto-cleared)
  • Incognito / private browsing mode
  • Choosing Cancel on the restore prompt
If auto-save fails 3 times in a row (storage full or disabled), the editor warns you and prompts a manual download. Don't ignore that toast.

Best Practices

  • Markers in titles or headings: if a marker lands at the start of a heading, move it to the start of the first body paragraph instead. This produces cleaner EPUB rendering and avoids disrupting heading styles.
  • Two-column magazines: when both columns on a page start a different article, you'll see two markers with the same page number (e.g. two 36s). That's correct — they get distinct internal IDs (page36, page36-2).
  • Re-editing a single article: use Copy Body Content, paste the article into a fresh file, edit its markers, then copy back into the larger document.

Troubleshooting

"Copy Body Content" does nothing or shows an error

The browser's Clipboard API is restricted when the page is opened from a file:// path. The editor will tell you to use Download instead. To restore clipboard support, host the editor at http(s):// or use a browser that allows clipboard access for local files.

The downloaded HTML looks different from my original

The editor uses the browser's XMLSerializer to write the file, which:

  • Adds a <!DOCTYPE html> declaration if missing
  • Collapses whitespace and indentation
  • May reorder attributes (e.g. class before id)

The content and structure are identical — only formatting changes. This is safe for EPUB generation. It's not suitable if you need byte-for-byte preservation.

My work disappeared after reopening

  • You may have clicked Cancel on the restore prompt. Auto-save data is then cleared.
  • You're in incognito / private mode — no persistent storage between sessions.
  • It's been more than 7 days since you last opened it.

Markers won't drag

Make sure you click directly on the red badge (not on a word next to it). The cursor turns into a grab hand when the marker is hoverable.

I added a marker but the page number is wrong

Double-click the marker, type the correct number, and confirm. The editor doesn't auto-renumber existing markers — sequential numbering is suggested only when adding new ones.

Known Limitations

  • Single-file constraint: the editor is one HTML file with no build step, no frameworks, no server. This is intentional for portability — the trade-off is that styling can't be shared across tools without duplication.
  • Output formatting: as noted above, downloads are reformatted by XMLSerializer. Content is preserved exactly; whitespace is not.
  • localStorage scope: auto-saved data is scoped to the file's URL in the browser. If you move the HTML file to a different folder, the saved work won't follow.

Where Markers Come From

This editor is the manual-correction step of a larger pipeline:

  1. Extract — rx-pagemarker extract reads a PDF and produces a JSON list of page-ending snippets.
  2. Mark — rx-pagemarker mark inserts marker <span> elements into the HTML at those snippet locations.
  3. Correct (this editor) — drag-and-drop any markers that landed in the wrong place.
  4. Generate — feed the corrected HTML to the EPUB generator for page-list navigation.

Each marker is a <span> with id="pageN", class="page-number", role="note", and aria-label="Page N" — these enable EPUB page-list navigation, citation parity with the print edition, and screen-reader accessibility.
